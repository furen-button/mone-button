# まとめ動画の YouTube 投稿計画

## 目的

`npm run createVideo` の出力を YouTube へ継続的に公開する。本ドキュメントは「何を出すか（ラインナップと並び）」「どう上げるか（手順とメタデータ）」「出す前に何を潰すか（ブロッカー）」を確定させる。

素材は 2026-08-16 時点で **109クリップ / 実尺 757.7 秒（12.6 分）/ 16 配信**しかない。1 本で使い切らず、総集編 → カテゴリ編 → Shorts の 3 段で回す前提で設計する。

カテゴリ分布: 世界 53 / やられ 22 / あいさつ 14 / 笑い声 6 / 散 6 / コラボ 4 / 即落ち 2 / 学び 2 / 泣き・ガハハ・お歌・へんたい 各 1。

配信別の本数上位は 2024-07-13 マリオ 19、2026-07-22 ゴエモン 18、2024-06-22 初配信 17、2024-08-17 カービィ 17。

## 公開前ブロッカー

公開品質に直結する 4 点。**すべて #1 の公開前に潰す。**

### 1. 素材解像度（`--source cache` 必須）

`public/videos/*.mp4` は Web 用の 200p（実測 **256×144** / crf28）。既存の `output/*.mp4` は 1920×1080 だが、256×144 からの引き伸ばしにすぎず YouTube 公開品質にならない。

公開用ビルドは必ず `--source cache`（高画質 DL + `ffmpeg-normalize`）を使う。cache 未取得の videoId は初回実行時に自動 DL されるが時間がかかるため、事前に流しておく。

2026-08-16 時点で未取得: `ewRvTOqk2es` / `AIuNhL8MueI` / `aMdcaHJPCj0` / `IFjGrAjQT5Q`（コラボ 2 配信を除外した場合）。

### 2. serif がプレースホルダのまま 15 本

serif が「あいさつ」「わらいごえ」「おはようございます」のままの clip JSON が 15 本あり、そのラベルがテロップとして焼き込まれる。実音声に合わせて書き起こす。

加えて、初配信の自己紹介 `2024-06-22-eguxJoekMyM-000097-000107.json` の serif が **「梢萌音」**（正しくは梢桃音）。#1 の冒頭に来るクリップなので最優先で直す。

### 3. 区間重複 5 組

同一 videoId 内で範囲が重なる sub-clip があり、時系列に並べると同じ音声が 2 回鳴る。長い方を残し、短い方を公開用ビルドから外す。

| 残す | 落とす |
|---|---|
| `2024-07-13-gr9WJDYS_u0-009960-009973` | `-009971-009973` |
| `2024-07-13-gr9WJDYS_u0-026720-026728` | `-026724-026728` |
| `2024-08-17-I98FMV6lWHQ-016134-016138` | `-016133-016135` |
| `2024-10-14-6AhNmLzAPaA-000117-000126` | `-000117-000121` |
| `2026-07-22-n5QHz9H5Rq0-001048-001054` | `-001053-001054` |

`public/data` 側は Web アプリ用にそのまま残し、**除外は createVideo の config 側で行う**（ボタンとしては個別に鳴らせたほうがよいため）。

### 4. 概要欄の文字数超過

現行 `summary.js` 形式で全 109 本の出典を書くと **8,809 文字**。YouTube 概要欄の上限 5,000 文字を 3,809 文字超過する。配信単位（16 本）へ圧縮すれば **1,586 文字**で収まる。

→ 概要欄には配信単位の出典のみ載せ、クリップ単位の一覧は固定コメントかもねボタン本体へ逃がす。

## 権利の pre-flight

- 概要欄に必ず入れる: 元配信の URL / 非公式のファン制作である旨 / 権利表記 / 公式チャンネルへの導線。

- **コラボクリップ 4 本**（`G_mYXnW5pqw` の珠乃井ナナ 3 本、`RlKaZjPgNdY` の石神のぞみ・栞葉るり・周央サンゴ 1 本）は共演者側の条件も関わる。確認が済むまで公開ビルドから外す。

## アップロード手段

### 方針: 手動アップロード + メタデータ自動生成

YouTube Data API `videos.insert` による全自動化は、現時点では割に合わない。

- 未監査の API プロジェクトからのアップロードは **private 固定**になる（結局 Studio で公開操作が必要）。※ポリシーは変わりうるので、自動化に踏み込む時点で再確認する。
- quota が 1 本あたり 1,600 units（既定の日次 10,000 units = 6 本/日）。
- 月に数本の運用では自動化の開発コストを回収できない。

よって **アップロード操作は Studio で手動**、**概要欄・タイトル・タグ・チャプターは createVideo 側で自動生成**という分担にする。

将来自動化する場合は `googleapis` + OAuth installed-app flow で private 投稿 → Studio で公開、の構成にする。

### チャプターの制約

YouTube のチャプターは **先頭 0:00 必須 / 3 つ以上 / 各区間 10 秒以上**。本データはクリップが 2〜4 秒中心のため、**クリップ単位のチャプターは規格上成立しない**。

→ チャプターは**配信ブロック単位**で切る。1 本しかない配信（ラーメン / マリカ / 428）は隣接ブロックへまとめるか、単独で 10 秒を超えることを確認する。

### summary.js の拡張（実装済み 2026-09-10）

現行の `output/<name>.txt` を、用途別に 3 系統へ分ける。

| 出力 | 用途 | 備考 |
|---|---|---|
| `<name>.youtube.txt` | 概要欄にそのまま貼る本文 | チャプター + 配信単位の出典 + サイト URL + 非公式表記。5,000 文字上限を超えたら警告する |
| `<name>.comment.txt` | 固定コメント用のクリップ単位一覧 | 同じく 5,000 文字上限。超過時は分割 |
| `<name>.meta.json` | タイトル案 / タグ / チャプター配列 | 将来の API 自動化でそのまま食わせる |

チャプター境界は「直前のクリップと videoId が変わった位置」で、時刻は既存の実尺積み上げロジックを流用する。10 秒未満のブロックは直前へマージする。

実装した挙動と、実データ 99 クリップでの結果:

- 先頭チャプターは必ず 0:00 に丸める（OP カードのぶん最初のクリップは 0 秒に来ないため）。
- 10 秒未満の区間は直前へ吸収する。先頭だけは吸収先が後ろになるので、始点 0 を保ったままラベルは後続を採る。
- マージ後に 3 個未満なら規格を満たさないので、警告して概要欄からチャプター節ごと落とす。
- ラベルは配信タイトルの末尾 `【演者名/所属】` を落とし、先頭 `【X】Y` を `X - Y` に整形する。配信によっては `『 にじさんじ / 梢桃音 』` 表記があるため `『』` も対象にし、残った区切り記号も落とす。
- **同じ配信が離れた位置で再登場する**（総集編は末尾に「散っ！」を集めるため）ので、`labels` は `videoId` に加えて `videoId#2` の形で出現回ごとに指定できる。
- 固定コメントは分割すると 2 つ目以降が出典不明で始まってしまうため、各塊の先頭では必ず配信タイトルを出す。

実測（`config-matome-01.json` / 99 クリップ / 756.6 秒）:

| 出力 | 文字数 | 備考 |
|---|---:|---|
| `.youtube.txt` | 2,156 | チャプター 19 個 + 出典 14 件。上限 5,000 に収まる |
| `.comment-1.txt` | 4,967 | 上限で分割 |
| `.comment-2.txt` | 3,426 | 先頭に出典タイトルあり |

チャプター 19 個は 12.5 分の動画にはやや多く、末尾の 5 個は「散っ！」フィナーレで既出配信が再登場したもの。公開前に `summary.chapters.labels` で `videoId#2` を使って命名するか、`minSec` を上げて間引くか判断すること。

## 公開ラインナップ

### #1 総集編（最初の 1 本）

設定は `scripts/create-video/config-matome-01.json`。**99 本 / 約 12.5 分**。

タイトル案: 「【梢桃音】初配信から3Dお披露目、そして今【にじさんじ/切り抜き】」

構成は**時系列（配信順）、ただし前後だけ手当てする**。

| 位置 | 内容 |
|---|---|
| オープン | 初配信の自己紹介 15 本（はじめまして → 蘭阜の調香師 → 天邪鬼と自由人 → 1000 年生きた魔法使い → 黙ってれば大丈夫だからね） |
| 本編 | マリオ → ラーメン → ナタデココ → カービィ → DQ2 → 428 → 3.0 お披露目 → 雑談 → 3D お披露目 → 振り返り → サザエ → ワリオ → ゴエモン |
| クローズ | 初配信から抜いておいた「記憶に残ってやる」→「またみんな見に来てね バイバイ」 |
| フィナーレ | 「散っ！」6 連発 |

並べ替えの意図:

- **「散っ！」6 本を本編から抜いてラストへ集約する。** 6 配信に散在する締め文句で、時系列配置だと同じ台詞が 6 回出て単調になる。集約すると決め台詞コレクションとして効き、そのまま Shorts 素材にもなる。
- **初配信の締め 2 本を末尾へ回す。** 初配信は最良のオープンと最良のクローズを両方持っているため、時系列のまま置くと締めが冒頭で消費される。
- **「しめさばざんまい」72 秒を外す。** 2〜4 秒の montage に 72 秒の歌が入ると流れが切れる。単体で出す。

除外は計 10 本（重複 5 / コラボ 4 / お歌 1）。

## 一括ビルド（local.sh）

予定している全動画のビルドは `./local.sh` にまとめてある。

```bash
./local.sh              # 全部（#1 を直列 → #2〜#5 を並列）
./local.sh --list       # ビルド対象の一覧
./local.sh --only 02    # 指定の 1 本だけ
./local.sh --sequential # 並列化せず 1 本ずつ
```

**#1 を先に単独で流し、その後 #2〜#5 を並列にする**構成になっている。`--source cache` の高画質 DL は #1 で全部済み、**#2〜#5 のクリップは #1 の部分集合**（検証済み）なので、以降はネットワークを使わず安全に並列化できる。並列を先に始めると同一 videoId を同時 DL する競合が起きうる。

実測（1920×1080 / zoom full / cache 済み）で **出力 1 秒あたり約 0.63 秒**のビルド時間。5 本の出力は合計約 24 分ぶんなので、全部直列なら約 15 分、#1 のあと #2〜#5 を並列にして約 12 分。

各ビルドの選択本数（除外適用後）:

| | 本数 | クリップ実尺 |
|---|---|---|
| #01 総集編 | 99 | 648 秒 |
| #02 世界 | 50 | 290 秒 |
| #03 やられ | 22 | 116 秒 |
| #04 あいさつ | 13 | 120 秒 |
| #05 笑い声・ガハハ | 5 | 42 秒 |

除外リストは `local.sh` の `EXCLUDE` に一元化してあり、`--exclude` で全ビルドへ渡す。**`--mode category` は除外を知らないため、これが無いと #2 / #4 / #5 に重複クリップとコラボクリップが混入する**（#2 に 3 本、#4 に 1 本、#5 に 2 本）。

`local.sh` は起動時に serif プレースホルダの残数を警告する。焼き込んでからの作り直しを防ぐため。

## 検証

- 出力が 1920×1080 / 30fps で、**引き伸ばしでない**こと（`--source cache` が効いているか ffprobe と目視で確認）。
